# 自律実行プロンプト

`docs/agent_harness.md` を導入済みのリポジトリでは、次の一行でタスクを開始できる。

```text
Task 010やって
```

エージェントは `CLAUDE.md` → `AGENTS.md` → `docs/agent_harness.md` を読み、モード判定・調査・設計・実装・検証・独立レビュー・修正・PR・CI追跡まで進める。人間の承認を待って止まるのは、`docs/agent_harness.md` §5「人間へのエスカレーション」に該当する場合だけ。

## 補足したいときの追記

短い指示に、必要な分だけ足す。

```text
Task 010やって。Deepモードで。通知の宛先はstaging限定にして、実配信はしないで。
```

```text
Task 010やって。まず設計案を2つ出して比較してから実装して。
```

```text
Task 010やって。今日はPRまで。CIが赤なら原因だけ報告して。
```

## 計画だけ見たいとき

自律実行させず、計画の確認だけしたい場合はPlan Modeで起動する。

```text
tasks/010-*.md を読んで、Plan Modeで変更予定ファイル・実装方針・受入条件との対応・リスクを提示してください。まだ編集しないでください。
```

## タスクファイルがまだない作業を頼むとき

`tasks/_template.md` を埋めさせてから実行させる。

```text
「オファーの通知メールを送る」をタスク化してください。tasks/_template.md に従って tasks/010-*.md を作り、
Goal / Source of truth / In scope / Out of scope / Acceptance criteria / Test plan / Rollback を埋めてから、
不明点があれば質問してください。実装はまだしないでください。
```

## 途中で止まったとき

```text
どこまで終わって、何で止まっているか、次に何をすれば進むかを教えてください。
```

エスカレーションされた場合、エージェントは「確認した内容」「決められない点と選択肢」「推奨」を添えている。判断だけ返せば続行する。

## 完了時に返ってくるもの

```text
実装概要:
変更ファイル:
受入条件への対応:
実行した検証:
PR / ブランチ / commit:
CI:
残る課題・リスク:
```

## 期待どおりに動かないとき

- 承認待ちで止まる: `CLAUDE.md` の「自律実行」節と `docs/agent_harness.md` §5 を確認する
- 検証せずに完了と言う: `docs/agent_harness.md` §4 Definition of Done を確認する
- スコープを越える: タスクファイルの Out of scope が空でないか確認する
- 同じ失敗を繰り返す: `docs/agent_harness.md` §8 ハーネス改善ルールに従い、仕組み側を直す
