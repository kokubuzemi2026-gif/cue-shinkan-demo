# Claude Code 個別タスク用プロンプト

タスクファイル（`tasks/NNN-*.md`）が整っている場合は、`prompts/autonomous_task.md` の一行指示で足りる。

このテンプレートは、タスクファイルがまだない作業や、範囲を明示的に絞りたい作業で使う。1回のプロンプトで1タスクだけ依頼する。

```text
あなたはこのリポジトリの実装担当です。自律実行してください。

## タスク
[タスク名]

## 目的
[この変更が誰の何を改善するか]

## 最初に読むファイル
- CLAUDE.md
- AGENTS.md
- docs/agent_harness.md
- docs/decisions.md
- [今回必要な仕様書]
- [対象タスクファイル]

## 変更してよいファイル
- [path]

## 変更してはいけない範囲
- [out of scope]

## 実装要件
1. [要件]
2. [要件]
3. [要件]

## 受入条件
- [画面または動作として確認できる条件]
- [エラー・空状態・ローディング状態]
- [スマートフォン390pxでの表示]
- [テスト条件]

## 作業手順
1. 実行モード（Fast / Standard / Deep）を宣言する。
2. 関連ファイルを読み、変更予定ファイルと実装方針を提示する。提示後は承認を待たずに実装へ進む。
3. 受入条件を左右する重大な矛盾がある場合だけ、実装前に質問する。
   軽微な曖昧さは最小の解釈で実装し、その解釈を報告に残す。
4. 実装する。commitは意味のまとまりごとに分ける。
5. lint、typecheck、test、buildを実行する。失敗したら原因を特定して直す。
   コマンドが失敗しただけで停止しない。
6. 独立レビュー（reviewer、該当すればsecurity-reviewer）を通し、Blockerを解消する。
7. feature branchへpushし、developへのPRを作成する。CIがgreenになるまで自分で追跡・修正する。
   自動マージはしない。
8. 変更概要、変更ファイル、検証結果、仕様との対応、PR/CI、残るリスクを日本語で報告する。

無関係な修正、依存関係の追加、仕様にない機能追加は行わないでください。
実行していない検証を、合格として報告しないでください。
```
